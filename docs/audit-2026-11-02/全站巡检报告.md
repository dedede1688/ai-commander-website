## 一、首页首屏价值传达与 CTA 评估

### 结论
**桌面端 1 屏内基本完成，但存在 1 处硬伤（移动端首屏失效）+ 3 处传达缺口。**

| 维度 | 判定 | 依据 |
|---|---|---|
| 价值主张 | ⚠️ 部分达成 | 首屏 H1 是品牌口号「AI 是参谋，你是司令」，**书名《AI指挥官》不在任何标题位**，只出现在 CTA 按钮文字里 |
| 一句话价值 | ✅ 达成 | hero-copy「从一本实战手册，到一套工作方法。判断任务、组织工具、核查结果，把AI用进工作与经营。」14px，位于 y=317 |
| 目标读者 | ❌ 缺失 | 首屏无「无需编程基础」这类受众锚点（book.html 有，index.html 没有） |
| 证据支撑 | ⚠️ 偏弱 | hero-facts 仅「8篇31章 / 9项附录 / 23位联合出版人」，是结构参数不是可信度；对比 book.html 另有「378 页」 |
| 主 CTA 清晰度 | ✅ 达成 | 「了解《AI指挥官》 →」teal 实底 + 深蓝字，44px 高，视觉权重第一 |
| 次 CTA 清晰度 | ⚠️ 偏弱 | 「查看个人实战课 →」与主 CTA 同为 44px 高、同级视觉权重，主次未拉开 |
| 1 屏内完成 | ✅ 桌面达成 | 1440×900 下标题(244) + 价值句(317) + 双 CTA(368) + 数据行(496) 全部落在首屏 |
| 1 屏内完成 | ❌ 移动端失败 | 390px 下 CTA 完全被裁掉（见 P0-01），首屏只剩标题残句 |

**建议的最小改动**：把「378 页」「无需编程基础，也能开始」补进 index 首屏，主 CTA 文案从「了解《AI指挥官》」改为动作导向（当前「了解」指向书名，转化路径模糊），次 CTA 降一档。

## 二、P0 级问题清单（必须改）

### P0-01 ｜ 首页首屏移动端横向破版 + 主 CTA 完全不可见
- **现象**：390px 视口下 document.scrollWidth = 1080px（视口仅 390px），页面横向撑出 690px 空白条；且首屏两个 CTA 被 hero 的 overflow:hidden 裁切，**用户根本点不到主 CTA**。
- **根因**：index.html:81 的 .rpt-head 带内联 width: 1068px; height: 467.516px;，内联宽度优先级高于 home-book.css:205 的移动端 display:flex 栅格，导致 hero 恒为 1068px 宽、467.5px 高的固定盒子。CTA 落在 y=570~614，超出 hero 底边 563，被裁切。
- **影响视口**：≤1280px 起横向溢出（实测 1024/834/768/414/390/360 全部 scrollWidth 1040~1084）；≤768px 起 CTA 被裁。
- **文件位置**：index.html:81（.rpt-head 内联 style）
- **截图**：screenshots/P0-01-index-mobile390.png、screenshots/P0-02-index-mobile-hero-clipped.png
- **修复建议**：删除 index.html:81 的内联 style 属性即可。home-book.css 与 style.css 已有完整的移动端栅格与 min-height:44px 规则，无需新增 CSS。

### P0-02 ｜ 首屏数据行被固定高度裁切并上移错位
- **现象**：.hero-facts 内联 height:20px，但实际内容（<b> 18px 字号 × 行高 1.75）高 26px，bTopRel=21 说明文字底边已溢出盒外；transform: matrix(1,0,0,1,0,-13) 又把整行上移 13px，与上方留白错位。
- **文件位置**：index.html:84（.hero-facts 内联 style）
- **截图**：screenshots/hero-index-1440x900.png（分隔线与数据行的间距异常）
- **修复建议**：删除该行内联 style 的 width/height/transform，改由 CSS 控制。

### P0-03 ｜ 书封被横向拉伸 19%，观感廉价
- **现象**：原图 426×640（宽高比 0.666），渲染为 230×290（宽高比 0.793），object-fit: fill 导致封面横向变形 19%。封面是首屏最大视觉资产，直接影响专业感。
- **文件位置**：index.html:85（img 内联 width:230px; height:290px），覆盖了 home-book.css:68 的正确写法 width:220px; height:auto
- **截图**：screenshots/hero-index-1440x900.png
- **修复建议**：删除内联 style，保留 CSS 的 height:auto 即可恢复原比例。

### P0-04 ｜ models.html「了解这本书」按钮锚点失效
- **现象**：链接指向 index.html#sec-book，但 index.html 的书籍区实际 id 是 book-summary（index.html:92），全站无 sec-book（该 id 只存在于 docs/archive/ 的归档页与 explore.html 的说明表中）。点击后滚动落空，停在页顶。
- **文件位置**：models.html:181
- **修复建议**：改为 index.html#book-summary。这是全站唯一一处真实失效的跨页锚点。

### P0-05 ｜ 4 个页面的二维码弹窗「关闭」按钮是浏览器原生样式
- **现象**：learning.html / outcomes.html / enterprise.html / cooperate.html 的 .qr-close 完全没有样式覆盖，计算值 background: rgb(240,240,240)、border: 2px outset rgb(0,0,0)、border-radius: 0、font-size: 13.33px——即浏览器默认灰色凸起按钮。而 index / book / builders 三页是正确的半透明圆形关闭钮（rgba(0,0,0,.55) + border-radius:50% + 22px）。
- **文件位置**：learning.html、outcomes.html、enterprise.html、cooperate.html 的 .qr-close 元素
- **截图**：screenshots/P1-learning-qr-close-unstyled.png（问题页） vs screenshots/P1-index-qr-close-styled.png（正常页）
- **修复建议**：把 index/book/builders 的 .qr-close 样式规则下沉到 base.css，4 个页面即自动修复。

### P0-06 ｜ 首页首屏 CTA 在移动端 100% 不可点（P0-01 的衍生后果）
- **现象**：390px 下 ctaFullyClipped = true，elementFromPoint 在 CTA 中心点返回 HTML（不是按钮），即命中的是背景而非可点元素。
- **文件位置**：同 P0-01（index.html:81）
- **截图**：screenshots/P0-02-index-mobile-hero-clipped.png
- **修复建议**：随 P0-01 一并解决。
