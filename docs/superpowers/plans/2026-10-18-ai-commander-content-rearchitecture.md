# 《AI指挥官》官方网站内容重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在最大限度保留原网站内容、原有语言和真实资料的前提下，把当前长首页重组为“精简首页＋独立栏目页＋成员个人页＋深度资料区”，先全盘安置内容，最后再由胡子老师确认隐藏或删除。

**Architecture:** 继续使用现有静态网站架构和视觉系统，不先推翻重做。第一阶段建立完整内容台账与事实口径；第二阶段将原内容按新页面架构迁移；第三阶段只对表达不清、状态过时、内容缺失或转化路径不完整的部分进行完善；最后建立保留、折叠、隐藏、归档、删除五级处置清单，未经确认不删除原内容。

**Tech Stack:** HTML、CSS、原生 JavaScript、现有静态成员页面、现有图片素材、Playwright（浏览器自动验收）

**Spec:** `docs/superpowers/specs/2026-10-18-ai-commander-website-design.md`

## Global Constraints

- 原网站内容和语言优先，不能为了页面简洁而直接重写或丢弃已有内容。
- 先盘点、再归类、再迁移、再完善、再补充，最后才决定隐藏或删除。
- “保留原文”“轻度完善”“补充新内容”“折叠展示”“迁移归档”“建议删除”必须有明确标记。
- 正式删除必须经过胡子老师逐项确认；计划执行阶段默认只迁移、折叠或隐藏。
- 书稿数据、作者经历、成员身份、席位数量、产品状态、课程状态和服务状态必须核实后发布。
- “已研发”“实际使用中”“开放筹备中”“规划中”必须严格区分。
- 首页只承担品牌定位、核心价值、可信证明和访问分流，完整内容进入独立页面。
- 继续沿用 `base.css`、`style.css` 与现有深蓝、浅灰、白色、青绿色视觉体系。
- 不修改未经授权的成员事实、案例和业务信息；成员私人联系方式本阶段不开放，预留功能但不在页面输出电话、微信、联系二维码或联系入口。
- 支付、真实表单、会员权限和佣金结算不属于本轮首期内容迁移范围。

## Review Focus

1. 原首页中的长篇图书内容、行业统计、共建指数和荣誉体系是否都找到新位置，不能因为首页缩短而丢失。
2. 23个成员页面的姓名、身份、席位、照片和简介是否与原站一致，不能在模板化迁移中串人或错位。
3. 书稿“八级成长路径”“九级军衔”“六层能力体系”等口径是否明确各自使用场景，不能混写。
4. 课程、俱乐部、商城、出版系统、私域助手和模型工具的当前状态是否真实，筹备内容不能表现成已上线。
5. 旧链接、分享链接、搜索信息和移动端导航在多页面改造后是否仍然有效，不能出现内容已经迁移但入口失效。

## 二、建议执行顺序与审核节点

### 第一阶段：只盘点，不改页面

完成 Task 1—3，交付内容总台账、事实基线和迁移矩阵。胡子老师确认内容归属后，再进入页面改造。

### 第二阶段：先完成核心访问路径

完成 Task 4—5，交付精简首页、图书详情和成果中心。确认网站的品牌表达和内容层级。

### 第三阶段：完成共建传播系统

完成 Task 6，先审核统一成员模板，再逐个迁移23位成员资料，避免批量错误。

### 第四阶段：完成商业与学习路径

完成 Task 7，建立企业服务、企业人工智能应用中心、学习工具和合作入口。

### 第五阶段：处理多余内容

完成 Task 8。先折叠、迁移和归档，最后才对经确认内容执行隐藏或删除。

### 第六阶段：全站验收

完成 Task 9，形成可追踪的验收报告，再决定是否替换正式网站。

## 三、首轮需要胡子老师审核的交付物

首轮不改正式页面，只提交以下三份文档：

1. `原网站内容总台账.md`：原网站到底有什么；
2. `事实口径与状态基线.md`：哪些事实已经确认，哪些仍待核实；
3. `内容迁移与处置矩阵.md`：每一项内容未来放在哪里、如何展示。

只有这三份内容得到确认后，才开始正式页面迁移。这样可以最大限度避免误删、漏搬、过度改写和内容口径冲突。
